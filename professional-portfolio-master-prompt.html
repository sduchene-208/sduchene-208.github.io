Reusable AI Prompt

Professional Portfolio Website Builder — Master Prompt

A profession-agnostic framework for turning a résumé/CV into a polished, evidence-driven professional portfolio.

Instructions

I want you to help me create a polished, modern professional portfolio website using my attached resume/CV as the primary source of truth.

The website will be hosted on GitHub Pages, so it must be a completely static website.

Do not assume I work in technology. The portfolio must adapt to my profession, experience, audience, and type of work.

PHASE 1 — Analyze My Professional Background

First, carefully analyze my attached resume/CV. Identify:

  • Professional title/identity
  • Industry or profession
  • Years of experience
  • Career progression
  • Core areas of expertise
  • Skills
  • Tools/technologies, if applicable
  • Education
  • Certifications/licenses
  • Awards or recognitions
  • Major accomplishments
  • Projects
  • Initiatives
  • Publications/research, if applicable
  • Leadership experience
  • Domain expertise
  • Evidence of measurable impact
  • Types of problems I solve
  • Types of people/organizations I work with
Important: The resume is the primary source of truth. Do not invent employers, job titles, dates, degrees, certifications, licenses, projects, technologies, metrics, clients, accomplishments, responsibilities, publications, or awards. If information would be useful but isn't supported by the resume, identify it as something I could add later rather than making it up.

PHASE 2 — Identify My Professional Story

Before writing any code, determine:

1. Professional Identity

What should someone remember about me after visiting the site?

2. Value Proposition

What do I actually help organizations, customers, clients, students, patients, teams, or other stakeholders accomplish?

3. Differentiators

What makes my background different from someone with a generic version of my job title?

4. Evidence

Which experiences, projects, accomplishments, credentials, or work products best demonstrate my value?

5. Target Audience

Who is most likely to visit this website?

  • Recruiters
  • Hiring managers
  • Executives
  • Potential clients
  • Customers
  • Patients
  • Students
  • Employers
  • Collaborators
  • Academic institutions
  • Professional peers

Determine the most appropriate audience based on my resume and career.

PHASE 3 — Choose the Right Portfolio Strategy

Do not automatically use a technology portfolio template.

Determine what kind of portfolio best represents my profession. Possible categories include technology, business analysis, product management, project management, consulting, finance, accounting, marketing, sales, HR, operations, education, healthcare, nursing, medicine, law, engineering, architecture, research, science, government, nonprofit, communications, writing, journalism, design, creative arts, skilled trades, hospitality, or another professional field.

The final design should reflect the profession rather than forcing the person into a predetermined style.

PHASE 5 — Propose the Website Before Building It

Before generating any code, give me a concise Portfolio Design Brief containing:

  • Professional positioning: What the website should communicate about me.
  • Recommended visual style: e.g. premium enterprise, minimalist editorial, executive consulting, modern SaaS, creative portfolio, clean healthcare, academic/research, professional services, industrial/engineering.
  • Recommended color direction: Include specific colors.
  • Recommended typography: Explain the general typography approach.
  • Recommended sections: Explain which sections you recommend and why.
  • Signature visual: Explain what visual centerpiece you recommend and why.
  • Featured work: Identify which experiences/projects from my resume should receive the most attention.
  • Primary call to action: Recommend the most appropriate CTA.
Do not generate the website yet. Wait for me to approve the strategy or request changes.

PHASE 6 — Build the Website

After I approve the strategy, build the website using semantic HTML5, CSS3, and vanilla JavaScript. Do not use React, Vue, Angular, Bootstrap, Tailwind, or other frameworks unless I specifically request them.

Create:

index.html
styles.css
script.js
README.md

If a resume PDF is provided, create an appropriate /assets/ directory.

PHASE 7 — Website Structure

Use semantic HTML5: <header>, <nav>, <main>, <section>, <article>, and <footer>.

Consider Hero, About, Capabilities, Selected Work/Case Studies, Experience, Credentials, Education, Publications/Research, Services, Testimonials, and Contact—but do not include unnecessary sections simply to follow a template.

PHASE 8 — Hero Section

The hero should immediately answer: Who am I? What do I do? What value do I provide?

Avoid generic headlines such as “Welcome to my portfolio.” Create a strong headline based on my actual professional identity. Use a strong headline, positioning statement, appropriate CTAs, and a signature visual or professional concept.

PHASE 9 — Signature Visual

If my profession supports a meaningful process or system visualization, create one using HTML/CSS/SVG, not a static image.

Each visual card should contain an icon or visual identifier, title, and short supporting text. Supporting text must be inside the cards. Do not place card descriptions underneath the cards.

The visualization must be responsive, accessible, subtly animated, independent of external dependencies, and never overlap other elements.

If a visual process is not appropriate, use a different centerpiece such as featured work, before/after comparison, timeline, data visualization, portfolio gallery, case study, credential display, research visualization, or professional methodology.

PHASE 10 — About Section

Write a professional first-person narrative based on my resume. Do not simply copy the resume summary. Explain what I do, what I care about professionally, what problems I solve, how I approach my work, and what differentiates me. Tone: confident, professional, authentic, and human.

PHASE 11 — Skills / Capabilities

Do not create a giant keyword wall. Group skills into meaningful categories and adapt them to my profession. Focus on capabilities, not just software names.

PHASE 12 — Projects / Selected Work

Choose the strongest projects, accomplishments, or professional experiences from my resume. Do not invent projects. The section may instead be called Selected Work, Case Studies, Professional Highlights, Research, Publications, Teaching Portfolio, Clinical Experience, Campaigns, Client Work, Major Initiatives, or Professional Accomplishments.

For each featured item, emphasize context, problem, my role, what I did, skills used, outcome, and impact. Prioritize the story and result over a list of responsibilities.

PHASE 13 — Experience

Present my career history in a visually engaging way. Do not simply reproduce the formatting of my resume. Show organization, position, dates, brief role description, and selected accomplishments. Make career progression easy to understand.

PHASE 14 — Credentials

Include relevant degrees, certifications, licenses, awards, professional memberships, training, publications, and continuing education when supported by the resume. Credentials should support the professional story rather than dominate the site.

PHASE 15 — Resume / CV

Include a prominent way to access my resume. If I provide a PDF, make it available for download.

/assets/FirstName-LastName-Resume.pdf

Include a Download Resume/CV button where appropriate.

PHASE 16 — Contact

Create a clean contact section appropriate to my profession. Possible options include email, LinkedIn, GitHub, professional website, portfolio, booking link, or professional social profile. Do not create a backend contact form; use static links such as mailto: when appropriate.

PHASE 17 — Privacy and Confidentiality

Never expose confidential information such as patient information, student identifying information, client confidential information, proprietary company information, private financial information, internal systems information, confidential case information, or inappropriate personal information. Describe confidential work at a safe professional level.

PHASE 18 — Visual Design

The visual design should match my profession. Do not automatically use a dark technology aesthetic.

  • Technology: sophisticated, technical, architectural
  • Finance: clean, authoritative, data-oriented
  • Healthcare: trustworthy, calm, clean
  • Education: approachable, organized, warm
  • Legal: elegant, restrained, authoritative
  • Creative: visual, expressive, editorial
  • Engineering: precise, structured, technical
  • Consulting: premium, strategic, executive
  • Trades: practical, authentic, project-focused

Choose the appropriate visual language based on my profession and audience.

PHASE 19 — Responsive Design

The website must work properly on desktop, laptop, tablet, and mobile. Use CSS Grid, Flexbox, responsive typography, and media queries. Do not use floats. Include a mobile hamburger navigation.

Test for overflow, overlapping elements, long job titles, long project descriptions, small screens, touch-friendly buttons, and responsive visualizations.

PHASE 20 — Animation

Use subtle animation where appropriate: scroll reveal, hover states, smooth navigation, subtle background effects, interactive portfolio elements, and animated process diagrams when appropriate. Respect prefers-reduced-motion: reduce.

PHASE 21 — Content Editing

Make important content easy to modify. Use clear HTML comments such as:

<!-- EDIT: Replace this with your professional summary -->

Keep the bio, projects, contact information, social links, and resume link easy to locate and edit. Do not bury content inside JavaScript unless necessary.

PHASE 22 — Code Quality

Keep the implementation clean and maintainable. Use semantic HTML, CSS custom properties, organized CSS, descriptive class names, vanilla JavaScript, accessible navigation, ARIA attributes where appropriate, and keyboard-friendly controls. Avoid unnecessary JavaScript and dependencies.

PHASE 23 — GitHub Pages

The final project must work by uploading the files directly to GitHub.

username.github.io/
│
├── index.html
├── styles.css
├── script.js
├── README.md
│
└── assets/
    └── resume.pdf

Git commands

git init
git add .
git commit -m "Create professional portfolio"
git branch -M main
git remote add origin https://github.com/USERNAME/USERNAME.github.io.git
git push -u origin main

Then explain: GitHub → Repository → Settings → Pages → Deploy from a branch → main → / (root).

PHASE 24 — Iterative Development

Do not assume the first version is final.

  • Preserve what is already working.
  • Change only what I request unless another change is necessary.
  • Don't rewrite the entire website unnecessarily.
  • Don't introduce new design patterns without explaining why.
  • If something isn't working, diagnose the underlying cause rather than repeatedly patching the symptom.

Most Important Principle

Do not build a résumé on a webpage.

Build a professional digital portfolio that uses the résumé as its source material.

The visitor should understand:

WHO I AM
     ↓
WHAT I DO
     ↓
WHAT PROBLEMS I SOLVE
     ↓
HOW I APPROACH MY WORK
     ↓
WHAT I'VE ACCOMPLISHED
     ↓
WHY MY EXPERIENCE MATTERS
     ↓
HOW TO CONTACT ME

The portfolio should demonstrate professional value rather than simply claim it.

Final Instruction

Before generating any code, complete PHASES 1–5 and show me the proposed portfolio strategy. Wait for my approval before building the website.
